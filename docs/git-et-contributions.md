# GitHub et contributions de l’équipe

## État de l’historique

La vérification locale du 2 novembre 2026 trouve un seul nom d’auteur : Ybelis.
Aucun auteur Codex, OpenAI ou Copilot et aucune mention `Co-authored-by` correspondante
n’ont été trouvés dans les messages de commits. Il n’y a pas d’attribution automatique
à retirer dans cet historique.

GitHub associe les commits à un compte à partir de l’adresse de leur auteur.
Cette adresse doit être liée au compte GitHub concerné. Voir la
[documentation GitHub sur les contributeurs](https://docs.github.com/en/repositories/viewing-activity-and-data-for-your-repository/viewing-a-projects-contributors).
Le nom affiché dans Git ne prouve pas à lui seul qui a compris ou réalisé le travail.

## Travailler réellement à trois

Chaque membre clone le dépôt, utilise son identité Git et prend en charge un changement
qu’il comprend. Avant un commit, vérifier les fichiers sélectionnés et le diff. Une
relecture croisée permet de discuter les choix ; les changements sont ensuite intégrés
dans la branche principale.

| Partie | Travail concret à réaliser et expliquer |
|---|---|
| Données et sources | Vérifier un import, sa licence et ses repères ; documenter un cas de découpage ou une limite réellement observée |
| Modèle et recherche | Exécuter un exemple, expliquer extraction / recherche / comparaison ; vérifier une citation rejetée et une transition expliquée |
| Interface et évaluation | Faire les tâches de prise en main, expliquer les quatre cases de la matrice et corriger un problème réellement constaté |

Ces propositions ne sont pas des contributions déjà accomplies. Remplir le tableau du
README avec les actions réellement effectuées, leurs commits et les vérifications menées.
Le [plan de préparation](preparer-demain.md) détaille les points à connaître à l’oral.

Attribuer rétrospectivement des commits à des membres qui n’ont pas réalisé les changements
ne crée pas de contribution. Aucun historique fictif, commit vide ou date antidatée n’est
nécessaire pour organiser la suite du travail.

## Déclaration des outils

La liste des contributeurs Git et la déclaration des outils sont deux sujets distincts.
Le PDF du cours autorise les outils IA et demande de déclarer leur usage. Le README
conserve donc la description de l’assistance reçue. Chaque membre doit pouvoir expliquer
le système entier, y compris les limites des résultats.
